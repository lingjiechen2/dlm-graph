==============================================================================
Node-description SFT prompts (prompt_format = nd_describe / nda_describe)
==============================================================================

These are the exact strings produced by dllm/data/graph.py::_build_node_sample_nd,
serialized through the Llama-3-style chat template. The center node's own text
is NEVER shown to the model; the model must produce a templated description
from neighbor texts + the cls label.

Structure of input_ids (every sample):

  <BOS> <|start_header_id|> user <|end_header_id|> \n\n
    [neighbor block]
    \nPlease briefly describe the center paper.
  <|eot_id|> <|start_header_id|> assistant <|end_header_id|> \n\n
    [assistant target — supervised]

Labels are -100 everywhere except the assistant span (so TM-DLM masking/loss
only fires on the description).

------------------------------------------------------------------------------
Notes on supervision
------------------------------------------------------------------------------

- node_spans[0]   = the assistant span (used for TM-DLM masking).
- node_spans[1:]  = each kept neighbor's tokens inside the user-content region
                    (offset by content_offset = position of <|eot_id|> in the
                    empty user template).
- node_hops[0]    = 0  (center, but text is excluded — span only holds answer).
- node_hops[1:]   = hop distance of the corresponding neighbor.
- Length budget:  neighbors are truncated per `per_nb_budget`; if the resulting
                  template still overflows max_seq_len, the template (not the
                  answer) is trimmed so the assistant target always survives.
